## synchronized 锁升级过程

```
偏向锁 → 轻量级锁（CAS自旋） → 重量级锁（Monitor）
```

1. **偏向锁**：同一个线程反复获取锁，在对象头记录线程ID
2. **轻量级锁**：有线程竞争时，通过CAS自旋尝试获取
3. **重量级锁**：自旋失败次数达到阈值，膨胀为重量级锁，进入阻塞队列

## volatile

- **可见性**：写volatile变量时JVM会发送Lock前缀指令，将缓存行写回主存
- **禁止指令重排**：通过内存屏障（Memory Barrier）实现
- **不保证原子性**：i++ 分三步（读、改、写），volatile只能保证读到的值是最新的
- **适用场景**：状态标志、DCL单例双重检查

## ThreadLocal

### 原理
- 每个Thread内部有一个ThreadLocalMap
- ThreadLocal作为key，值是实际存储的对象
- Entry的key是WeakReference<ThreadLocal>

### 内存泄漏原因
- key是弱引用会被GC回收
- value是强引用，只要线程存在就不会被回收
- 线程池中线程复用，value一直存在

### 解决方案
- 使用完必须调用 `remove()` 方法

## AQS（AbstractQueuedSynchronizer）

### 核心组成
- **state**：volatile int，表示同步状态
- **CLH队列**：双向链表，存放等待线程
- **模板方法**：tryAcquire/tryRelease由子类实现

### 工作流程
1. 线程调用acquire()尝试获取锁
2. 调用tryAcquire()（子类实现）尝试快速获取
3. 失败则将线程封装为Node加入CLH队列
4. 前驱节点释放后唤醒当前节点

## ConcurrentHashMap

### JDK 7 vs JDK 8

| 维度 | JDK 7 | JDK 8 |
|------|-------|-------|
| 锁粒度 | Segment（16个） | 桶级别 |
| 并发度 | 16 | 高（桶数量） |
| 实现 | ReentrantLock | CAS + synchronized |
| 数据结构 | Segment + HashEntry | Node数组 + 红黑树 |

## 线程池

### 7个参数
```java
ThreadPoolExecutor(int corePoolSize,
                  int maxPoolSize,
                  long keepAliveTime,
                  TimeUnit unit,
                  BlockingQueue<Runnable> workQueue,
                  ThreadFactory threadFactory,
                  RejectedExecutionHandler handler)
```

### 任务提交流程
1. 当前线程数 < corePoolSize → 新建线程
2. 当前线程数 ≥ corePoolSize → 任务入队
3. 队列满了 → 新建线程，直到maxPoolSize
4. 超过maxPoolSize → 执行拒绝策略

### 四种拒绝策略
| 策略 | 说明 |
|------|------|
| AbortPolicy | 抛异常（默认） |
| CallerRunsPolicy | 由调用者线程执行 |
| DiscardPolicy | 直接丢弃 |
| DiscardOldestPolicy | 丢弃队列中最旧的任务 |

## synchronized vs ReentrantLock

| 维度 | synchronized | ReentrantLock |
|------|-------------|---------------|
| 实现 | JVM级别 | JDK API级别 |
| 锁释放 | 自动 | 手动（finally unlock） |
| 可中断 | 不支持 | lockInterruptibly() |
| 超时 | 不支持 | tryLock(timeout) |
| 公平锁 | 非公平 | 可公平可非公平 |
| 多条件 | 单一 | 多个Condition |
