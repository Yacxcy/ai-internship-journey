# 后端八股 — Redis 高频考点

---

## Redis 为什么快？

1. **基于内存**：数据在内存中，读写速度是纳秒级
2. **单线程模型**：避免上下文切换和锁竞争（6.0+引入IO多线程但命令执行仍是单线程）
3. **IO多路复用**：epoll/kqueue处理大量并发连接
4. **高效数据结构**：简单动态字符串、跳表、压缩列表等

---

## 缓存三大问题

| 问题 | 描述 | 解决方案 |
|------|------|----------|
| **缓存穿透** | 查询不存在的数据，请求打到DB | 布隆过滤器、缓存空值 |
| **缓存击穿** | 热点key过期，大量请求到DB | 互斥锁、逻辑过期、永不过期 |
| **缓存雪崩** | 大量key同时过期或Redis宕机 | 随机过期时间、Redis集群、限流降级 |

## Redis 数据结构

| 类型 | 底层实现 | 适用场景 |
|------|----------|----------|
| String | SDS（简单动态字符串） | 计数、缓存 |
| List | 双向链表/压缩列表 | 消息队列 |
| Set | 哈希表/整数集合 | 去重、标签 |
| ZSet | 跳表+哈希表 | 排行榜 |
| Hash | 压缩列表/哈希表 | 对象存储 |

## 持久化 RDB vs AOF

| 维度 | RDB | AOF |
|------|-----|-----|
| 原理 | 快照，fork子进程写入磁盘 | 追加写命令日志 |
| 性能 | 高 | 相对低 |
| 数据安全 | 可能丢失最后一次快照后的数据 | 更安全（可配置每秒fsync） |
| 恢复速度 | 快 | 慢 |
| 文件大小 | 小（压缩二进制） | 大（文本命令） |

**混合持久化（4.0+）**：RDB快照 + 增量AOF，兼顾恢复速度和数据安全

## 分布式锁

### 基础实现（SET NX PX）
```
SET lock_key unique_value NX PX 30000
```
- NX：只在key不存在时设置
- PX：设置过期时间（毫秒）

### Redisson WatchDog
- 自动续期机制：默认每10秒续期到30秒
- Lua脚本原子释放：检查value是否匹配再删除

## 过期删除与内存淘汰

### 过期删除
- **惰性删除**：访问时检查是否过期
- **定期删除**：定时随机扫描一批key检查

### 内存淘汰策略
| 策略 | 说明 |
|------|------|
| noeviction | 不淘汰，写入报错 |
| allkeys-lru | 从所有key中淘汰最近最少使用的 |
| volatile-lru | 从设置了过期时间的key中淘汰 |
| allkeys-lfu | 从所有key中淘汰使用频率最低的 |
| allkeys-random | 从所有key中随机淘汰 |

## 缓存与数据库一致性

### 常用方案
1. **先更新DB再删缓存**：最常用，配合延迟双删
2. **Canal订阅binlog**：监听DB变更，异步更新缓存
3. **先删缓存再更新DB**：不推荐，容易出现不一致
