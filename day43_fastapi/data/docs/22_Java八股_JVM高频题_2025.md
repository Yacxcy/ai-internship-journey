# Java 八股 — JVM 高频面试题

## JVM 内存模型

| 区域 | 归属 | 作用 |
|------|------|------|
| **程序计数器** | 线程私有 | 记录当前线程执行的字节码行号 |
| **虚拟机栈** | 线程私有 | 存储局部变量表、操作数栈、动态链接、方法出口 |
| **本地方法栈** | 线程私有 | 为 Native 方法服务 |
| **堆（Heap）** | 线程共享 | 存放对象实例，GC 主要区域（新生代+老年代） |
| **方法区（元空间）** | 线程共享 | 存储类信息、常量、静态变量、JIT 编译后的代码 |

## 垃圾回收算法

| 算法 | 特点 | 适用场景 |
|------|------|----------|
| **标记-清除** | 产生内存碎片 | 老年代（CMS） |
| **标记-复制** | 空间换时间，无碎片 | 新生代 |
| **标记-整理** | 无碎片，耗时长 | 老年代（Serial/Parallel Old） |
| **分代收集** | 新生代用复制，老年代用标记-清除/整理 | 主流 JVM |

---

## GC 收集器对比

| 收集器 | 特点 | 停顿时间 |
|--------|------|----------|
| **Serial** | 单线程，适合客户端 | 几十ms |
| **Parallel** | 多线程，吞吐量优先 | 几十ms |
| **CMS** | 并发标记清除，老年代 | 与CPU核数相关 |
| **G1** | 分Region，增量回收，JDK 9+ 默认 | 可预测停顿 |
| **ZGC** | 染色指针+读屏障，TB级堆 | < 10ms（JDK 11+） |

## Minor GC 与 Full GC

- **Minor GC**：Eden 区满时触发，回收新生代
- **Full GC 触发条件**：
  1. 老年代空间不足
  2. 方法区空间不足
  3. `System.gc()` 调用
  4. CMS 并发失败（Concurrent Mode Failure）

## 类加载机制

### 类加载过程
加载 → 验证 → 准备 → 解析 → 初始化

### 双亲委派模型
类加载器收到加载请求时，先委托父类加载器尝试加载，父类加载不了时子类才自己加载。

**破坏双亲委派的典型场景**：SPI 机制（如 JDBC），通过 `Thread.currentThread().getContextClassLoader()` 来加载。

## 对象晋升老年代的条件

1. **年龄阈值**：在Survivor区存活超过15次GC（-XX:MaxTenuringThreshold）
2. **大对象**：直接分配在老年代（-XX:PretenureSizeThreshold）
3. **动态年龄判断**：Survivor区中同年龄对象大小总和超过一半
4. **空间分配担保**：Minor GC时Survivor放不下
