# 系统设计面试题 — 分布式与高并发

---

## 分布式核心技术

### 分布式ID生成
- **Snowflake**：时间戳+机器ID+序列号，解决时钟回拨（序列号缓存）
- **号段模式**：数据库预分配ID段，用完再申请
- **Redis INCR**：简单但依赖Redis可用性

### 分布式锁
- **Redis**：`SET NX PX` + Lua原子释放，Redisson WatchDog自动续期
- **ZooKeeper**：临时顺序节点，节点删除即释放锁，更严格的一致性
- **RedLock**：多Redis节点投票

### 分布式事务
- **TCC**（Try-Confirm-Cancel）：灵活但代码侵入性强
- **Seata AT**：自动回滚undo log
- **RocketMQ事务消息**：半消息 + 事务状态回查
- **Saga**：长事务拆分为多个本地事务，补偿回滚

### 分布式限流
- **令牌桶**：固定速率生成令牌，允许突发流量
- **漏桶**：恒定速率处理，平滑流量
- **滑动窗口**：Redis ZSet记录时间窗口，精确到毫秒

## 高并发场景设计

### 10亿UV统计
- **HyperLogLog**：概率数据结构，标准误差0.81%，12KB可统计2^64个元素
- **位图 + 布隆过滤器**：精确统计

### 100G数据找Top 10
- **分治 + 小顶堆**：拆分成小文件，每个找Top 10，合并
- **MapReduce**思想：Map阶段分治，Reduce阶段合并

### 实时排行榜
- **Redis ZSet**：跳表实现，O(log n)更新分数
- **定时同步到DB**：分钟级批量同步

### IM群聊设计
- WebSocket长连接
- MQ扩散写：消息发到MQ，下游推送给所有群成员
- 离线消息拉取：用户上线后拉取未读消息

## 系统设计通用框架（面试回答步骤）

1. **需求分析** → 明确QPS、数据量、延迟要求
2. **容量估算** → 带宽、存储、缓存大小预估
3. **技术选型** → 存储（MySQL/Redis/ES）、中间件（Kafka/RabbitMQ）
4. **架构设计** → 画架构图，讲清楚流量链路
5. **核心难点** → 一致性、高可用、扩展性如何保证
6. **监控运维** → Prometheus + Grafana，熔断降级策略
