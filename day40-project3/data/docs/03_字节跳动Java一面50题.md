## Java 并发编程（80% 一面必问）

### synchronized 锁升级过程
偏向锁→轻量级锁→重量级锁，条件是什么？
- 偏向锁：只有一个线程访问时，在对象头记录线程ID
- 轻量级锁：有竞争时，通过CAS自旋获取
- 重量级锁：自旋失败后膨胀，进入Monitor

### volatile
可见性+禁止指令重排，为什么不能保证 i++ 原子性？
- i++ 分三步：读、改、写，volatile只保证可见性不保证原子性
- 适用场景：状态标志、DCL单例

### ThreadLocal 内存泄漏
WeakReference key + 线程池 → 必须 finally 中 remove()
- key是弱引用会被GC回收，但value是强引用
- 线程池中线程复用，导致value一直存在

### AQS 原理
state + CLH 队列 + tryAcquire 模板方法
- state用volatile修饰，保证可见性
- CLH变种队列，双向链表
- 模板方法模式：tryAcquire/tryRelease由子类实现

### ConcurrentHashMap
JDK7 Segment 分段锁 vs JDK8 CAS+synchronized 桶级别锁
- JDK7：16个Segment，并发度16
- JDK8：锁粒度到桶，CAS初始化，synchronized锁桶头节点

### 线程池
7个参数，任务提交流程（先 corePool→入队→maxPool→拒绝策略）
- corePoolSize, maxPoolSize, keepAliveTime, unit, workQueue, threadFactory, handler
- 四种拒绝策略：AbortPolicy, CallerRunsPolicy, DiscardPolicy, DiscardOldestPolicy

### synchronized vs ReentrantLock
锁升级、可中断、超时、多条件变量
- synchronized：自动释放，锁升级优化
- ReentrantLock：可中断lockInterruptibly()、tryLock(timeout)、多Condition

## Redis 高频考点

- **缓存穿透/击穿/雪崩**：区别 + 各自解决方案
- **Redis 为什么快**：内存+单线程免锁+IO 多路复用
- **持久化 RDB vs AOF**：fork COW、AOF 重写、混合持久化
- **分布式锁**：`SET NX PX` → Lua 脚本释放（验证 value）→ Redisson WatchDog 续期
- **ZSet 底层**：ziplist/listpack（小）或 skiplist+hashtable（大）
- **过期删除**：惰性删除 + 定期删除；**内存淘汰**：allkeys-lru（推荐）
