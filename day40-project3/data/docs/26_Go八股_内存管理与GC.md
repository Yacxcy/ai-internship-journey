## 逃逸分析

编译器决定变量分配在栈还是堆。

### 逃逸场景
- 返回局部变量指针 → 逃逸到堆
- 发送到 channel → 可能逃逸
- 闭包引用局部变量 → 可能逃逸
- interface{} 参数 → 可能逃逸
- 变量过大 → 逃逸到堆

### 栈 vs 堆
| 维度 | 栈 | 堆 |
|------|----|----|
| 分配速度 | 极快（移动SP指针） | 慢（需要查找空闲空间） |
| GC管理 | 不需要 | 需要GC回收 |
| 生命周期 | 函数返回后释放 | GC决定 |
| 大小限制 | 小（默认1KB～1GB动态） | 大 |

## GC — 三色标记法 + 混合写屏障

### 三色标记
- **白色**：未访问（潜在垃圾）
- **灰色**：已访问但子对象未扫描
- **黑色**：已访问且子对象已扫描

### 过程
1. 根对象（栈、全局变量）标记为灰色
2. 从灰色对象出发，将可达对象标记为灰色，自身标记为黑色
3. 重复步骤2直到无灰色对象
4. 白色对象即为垃圾

### 混合写屏障（Go 1.8+）
- 插入屏障 + 删除屏障
- 保证GC期间并发安全
- STW时间：亚毫秒级（Go 1.18+）

## pprof 性能分析

### 常见分析类型
- **CPU Profile**：定位CPU热点函数
- **Heap Profile**：内存分配和泄漏分析
- **Goroutine Profile**：goroutine数量和状态
- **Block Profile**：阻塞分析

### 使用方式
```go
import _ "net/http/pprof"
// 访问 http://localhost:6060/debug/pprof/
```

### 内存泄漏排查
1. `go tool pprof http://localhost:6060/debug/pprof/heap`
2. `top` 查看内存分配最多的函数
3. `list funcName` 查看具体代码
4. 对比不同时间点的heap profile
