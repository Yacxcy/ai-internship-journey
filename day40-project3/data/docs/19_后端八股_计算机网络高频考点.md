## TCP 三次握手/四次挥手

### 三次握手
1. 客户端发送 SYN（seq=x）
2. 服务端回复 SYN+ACK（seq=y, ack=x+1）
3. 客户端回复 ACK（ack=y+1）

**追问：为什么是三次不是两次？**
- 防止历史连接。如果只有两次握手，服务端收到SYN后就建立连接浪费资源
- 三次握手让双方都确认自己的收发和对方的收发都正常

### 四次挥手
1. 主动方发送 FIN
2. 被动方回复 ACK
3. 被动方发送 FIN
4. 主动方回复 ACK

**追问：为什么需要四次？**
- TCP是全双工的，双方都要关闭自己的发送通道

### TIME_WAIT
- 主动关闭方在收到最后一个ACK后等待2MSL
- 原因：①确保最后的ACK能到达 ②让旧连接的报文在网络中消失
- 大量TIME_WAIT处理：SO_REUSEADDR + tcp_tw_reuse

## TCP 可靠性保证

| 机制 | 说明 |
|------|------|
| 序号与确认 | 每个字节都有序号，接收方确认收到的数据 |
| 超时重传 | RTT自适应超时时间，超时后重传 |
| 滑动窗口 | 流量控制，接收方告知自己的窗口大小 |
| 拥塞控制 | 慢启动→拥塞避免→快重传→快恢复 |

## HTTP 各版本差异

| 版本 | 特点 |
|------|------|
| HTTP/1.0 | 短连接，每次请求新建TCP连接 |
| HTTP/1.1 | 持久连接（Keep-Alive）、管道化、Host头 |
| HTTP/2.0 | 二进制分帧、多路复用、头部压缩（HPACK）、服务器推送 |
| HTTP/3.0 | 基于QUIC（UDP），0-RTT握手，无TCP队头阻塞 |

## HTTPS / TLS

### TLS 1.3 握手（1-RTT）
1. Client Hello：支持的密码套件+密钥交换参数
2. Server Hello：选择密码套件+密钥交换参数+证书
3. 双方计算会话密钥，开始加密通信

### 0-RTT
- 对于重连会话，客户端可以在第一个包中就发送加密数据
